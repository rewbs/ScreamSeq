Find the checkout, then inspect `editor/TrackerDocument.hpp`, `editor/SignalGraph.hpp`, `editor/SignalRuntime.hpp`, and the relevant platform host. On macOS, `mac/Audio/NativeInstrument.cpp` connects the shared renderer to native plugins, automation and mixer adapters; `NativeSignalGraph.cpp` owns graph processor copies.

The audio callback cannot allocate, free, lock, log, touch UI, parse scripts, discover plugins, serialize state or construct processors. Prepare bounded buffers, schedules, formulas and graph plans on the control thread. Publish safely and retire old objects off the callback. Use the existing realtime allocation/free/lock audit; a passing functional test alone does not establish realtime safety. Vendor-private allocations are outside the host's audit guarantees.

Keep playback compatible when native features are absent. Use stock OpenMPT PCM comparisons across rates and callback sizes after changes to `soundlib/`. Native extensions are guarded by `OPENMPT_EDITOR_CORE`. Exact timing belongs to the engine clock: precise notes/graph commands use 65536 units per row; automation curves currently use 256. Convert musical coordinates with the actual pattern beat signature. MIDI recording maps incoming timestamps through `RecordingClock`, not UI delivery time.

Trigger a precise note only on its target voice/channel; do not fake whole-engine ticks. Onset effects apply at the onset; continuing tracker effects retain the ordinary tick clock. Account for note-off/cut, instrument NNA, repeated identical-note generations, loop entry and sample offset boundaries. Per-hit effects are validated against both the safe note-local whitelist and module format.

VST3 supports parameter queues with sample offsets inside a processing block. Send ramp endpoints through bounded queues; don't process 1-sample VST3 buffers to simulate slides. Preserve endpoint precision for partition-independent results. Test AU, VST3, built-ins, samples and instrument events separately because their automation/event contracts differ. Stable parameter IDs and native-versus-normalized values must not be confused.

Graph invariants: independent processors per target and row/persistent/ordinary role; row graphs precede persistent graphs, then the ordinary graph and regular inserts. A then B means A→B; repeating Start updates the existing entry. Inactive graphs process silence continuously, including sidechain inputs, while transport advances. Stop cuts graph output by default; optional tails remain at the retained stage. Downstream processors retain already-received audio. Reject cycles in each accepted graph. `MixerTransition` uses a union dependency DAG when old/new inputs can morph with each retained vendor advancing once. Union cycles, changed latency or prepared source/copy handoffs use a latency-aligned dry bridge with audio activation at a render-chunk boundary. Do not run a retained vendor twice or advance the sample clock during a transition. Keep prepared model/history publication atomic; `Document` native-only staged callbacks run before no-throw history adoption. Preparation, capacity or queue rejection preserves the old audible plan, transport and history. `commitStopped` requires a quiescent callback.

Rack/source and graph-copy changes prepare binding tables off the callback. Removed instrument assignments release only their owned notes; newly connected destinations wait for the next note-on. Preserve retained vendor and note/envelope histories, including inactive copies used by Undo. Count transient copy tables separately from retained vendors, but keep every reachable replacement/runtime owner in the combined storage budget. Detached effects process silence continuously. Native AU/VST3 providers prepare supported physical buses and expose deterministic stereo/odd-mono logical slices; use prepared capacity for a first live cable without vendor activation. Validate saved `audioLayout` fingerprints before applying state or wiring; unsupported or changed physical layouts reject. Latency notifications carry serials: prepare PDC/bypass delays on the control owner and acknowledge only the adopted generation without deactivating the vendor. Bus/parameter observation catalogs publish only after successful preparation, and removed copy domains retire at audio activation. Aggregate outer stage I/O represents the Row/persistent/ordinary stack, not a selected copy or an instrument graph; do not alias aggregate PCM as exact-copy routing.

Sample-instrument graphs use separate prepared copies per instrument and raw channel, before channel graphs. Route both the sample mix and its click-removal offsets consistently. New-note-action voices retain their original instrument and parent channel. Native plugin instruments instead use their audio output bus routes. Both graph stages share the processor/storage budget; the upstream adapter-slot budget is a separate bound. Do not scan note voices for graphs without a note-envelope source.

Graph automation uses stable pattern IDs and 256 units/row, while the native playback observer uses 65536. Pass the true pattern end and beat signature to scripts. Split at step boundaries; smooth segments use bounded 32-sample evaluations and host ramps. Test absent/disabled curves, pattern clones, final-node scripts and callback partition invariance.

`PluginChain::prepareGraphControls` publishes recipe parameters, source settings, modulation depth/base, pattern curves and audio-edge gains to every prepared copy at one render boundary. Structural node/edge, role/assignment and port changes prepare complete copy sets and mixer plans, reusing stable retained endpoints, then activate through the routing handoff. `GraphPluginEndpoint` replaces opaque recipe state with a bounded 10 ms old/new fade. Replacement must preserve descriptor, physical buses, latency and parameter identities/ranges. Compatible rack effect presets similarly replace vendors behind the stable `NativePlugin` facade so ramps and recorded cursors survive; instrument presets require stopped playback until held-voice replacement semantics are implemented and qualified. The producer-owned plan owns both fading incarnations; another opaque replacement waits for adoption and fade completion. Ordinary controls may coalesce during the fade and must fan out to both. Never infer a preset reload from stale saved state during an ordinary routing edit. Test later routing and manual writes so a previously published preset cannot replay or overwrite newer input.

Recipe stepped targets require explicit `SignalModulation.quantized`, matching mode on every enabled contribution, and a positive catalogue step. Sum sources and clamp once before quantizing. `SignalRuntime` owns fixed 32-sample values per target; `GraphPluginEndpoint` borrows them synchronously and fans them out to both preset incarnations. The host accepts at most 64 targets and streams at most 16 sample-offset VST3 points per parameter per audio call. Do not implement discrete VST control by scheduling one scalar musical event/audio call per sample. AU/builtins split at actual value changes. Keep Mac/Windows parameter step metadata aligned (VST normalized `1/stepCount`; AU/builtin indexed or boolean unit increments). Qualify actual discrete PCM, maximum-target queues, preset fanout, callback partitions, and absence of artificial one-sample VST calls; leave the continuous ramp path intact.

Reusable-graph or song-source edits can share one publication with normal parameter lanes (for linked envelope banks and Undo). Keep source/graph/musical revision guards coupled. A graph parameter snapshot is limited to 128 changed IDs per processor, reserving vendor queue space for pending updates and modulation. Runtime pointers must reference retained plans, not temporary API objects. Manual/preset values live in the control-owned rack catalogue; scheduled baseline cells belong to audio. The editable `manualValue` stays independent of the effective vendor value and the current pattern/recorded baseline. Song modulation adds to the latter, never feeds its own output back. Follower edges must use the actual current-block bus/plugin PCM and add scheduling dependencies; reject feedback cycles. Do not weaken queue/storage budgets to accommodate dense follower or quantized curves.

Keep tail budgets current after presets and decay controls, including sample-instrument previews and explicit tail-preserving graph stops.
