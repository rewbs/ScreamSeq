# ScreamSeq 0.1.0 compatibility and qualification

Independent OpenMPT derivative; macOS 14+ build target. Measured locally on an Apple M2 Pro MacBook Pro (Mac14,9, 32 GB) and macOS 26.5.2, using the built-in speakers through Core Audio at 48 kHz / 128 frames. Intel and other devices/OS versions have not been qualified.

## Editing and files

| Capability | Implemented and checked | Boundary |
|---|---|---|
| MOD, XM, S3M, IT, MPTM | Import, pattern/sample editing, native save/reopen, format-specific note/command/row/channel/sample limits | Supplied MOD/XM/S3M/MPTM fixtures plus generated IT and MPTM songs; this is not an exhaustive format corpus |
| Other tracker formats | Engine-based preview | Read-only; external-asset/plugin limitations are reported |
| Patterns and orders | Notes, volume/effect fields, rectangular clipboard, row operations, transpose, pattern duplication, full order insert/assign/move/remove, channel resize, grouped undo | Pattern batches up to 512 cells enter the live audio queue; larger/saturated changes stop transport while retaining document edits |
| Samples | Import/replace, rename, rate, volume/pan, forward/ping-pong loops, reverse/normalize/fades/invert/silence/trim, exact PCM undo | Structural operations stop transport; no continuous playing-asset swap yet |
| Instruments | ITI/XI import, volume/pan/pitch/filter envelopes, sustain/loop ranges, keymaps, new-note/duplicate-note settings | Node tick/value editing, keyboard adjustment and deletion checked; ITI/XI fixtures tested; SFZ/PAT import uses engine support but is not separately qualified |
| MIDI | CoreMIDI source/virtual input, audition, velocity, step and live row recording, panic, bounded multi-producer input | Virtual-source loopback, running status, note release and disconnect tested; overflow quarantines stale events and releases held notes. Row quantization; no timestamp-corrected sub-row recording or MIDI clock sync |
| Recovery | Three generations per document; newest valid recovery; failed-write retention; document-scoped cleanup | Recover is explicit via the File menu; unsaved discarded sessions can remain recoverable |
| Project | Versioned `.resonance` file containing native module bytes, AU/VST3 state, instrument assignments, automation and selected sequence | Module-only save refuses to discard native plugins; malformed metadata is rejected; missing plugins are preserved and repairable; saving while playing keeps transport running |
| Sequences | Select existing sequences in Arrange; chosen sequence survives native/project saving and governs playback/export; two-sequence reference renders at three rates | Sequence creation/renaming is not exposed |

## Native plugins

| Effect / feature | Qualification |
|---|---|
| Apple AULowpass, AUHipass, AUPeakLimiter | Parameter state recall, stereo finite output, live/offline equivalence, intercepted allocation/release/lock checks including first render |
| AULowpass automation | Exact comparison at 44.1/48/96 kHz across 128/512-frame buffers; host splits at event boundaries because relying on AU parameter offsets was insufficient |
| Apple AUDelay | Offline export compared sample for sample against a separately scheduled AU; approximately 21 seconds of reported tail retained |
| PeakLimiter export | Advertised leading latency removed and tail retained; independent render comparison |
| Other installed AUs | Separate-process discovery and candidate render/state probe with bounded time/output; not full qualification |

The rack accepts up to 64 built-in or native macOS AU/VST3 devices. Effects can occupy track/group/return/Master inserts, with pre/post sends and sidechain routes; instrument plugins are assigned to existing tracker instruments and receive OpenMPT’s tick-timed MIDI events. The stereo graph compensates sample, instrument, insert, send and sidechain paths, and offline export removes the complete reported graph latency. Instrument release tails and master-effect tails are retained within the existing 60-second export tail limit. AU and VST3 receive tempo, beat, time signature and transport information; instrument timing follows mixer chunks, while master-effect transport is refreshed once per device/export block.

VST3 component/controller state, native AU/built-in state, auxiliary activation, routing, instrument assignments, and parameter automation persist in `.resonance` version 4. Native metadata uses v4 by default, v5 for grouped note columns/mute overrides and v6 for nonzero mixer input balance. The reader still accepts project versions 1–3 and earlier native metadata. Older builds reject newer metadata instead of silently changing its sound. A shared budget of 250 core adapters covers mixer buses plus assigned plugin instruments, including bypassed assignments; effects consume no adapter slots. Native parameter controls and custom-editor gestures can record automation; playback and export split processing at automation sample positions. Rack add/remove/move/bypass, assignments, and automation clearing share bounded undo/redo history. Missing plugins retain their opaque state for repair.

Custom interfaces support macOS VST3 NSView editors and AU Cocoa editors. AUv3 view-controller interfaces are not yet implemented or qualified. AU creation, configuration, state/property access and disposal, plus VST3 controller/editor work, run on the main thread; the audio callback uses preallocated MIDI/parameter lists. Large native parameter lists use a searchable, recycled table. Unsupported custom editors fall back to native parameter controls. A plugin requesting changed buses or latency during processing stops the graph; automatic graph renegotiation is not implemented.

AU/VST3 plugins can declare up to 64 audio buses per direction. Main bus 0 stays active; supported mono/stereo auxiliaries can be explicitly enabled. Instrument outputs route independently without processing the instrument twice. Sidechain sources sum into enabled auxiliary effect inputs; source/receiver ordering and insert-prefix compensation are compiled. Unsupported surround auxiliaries remain unavailable. Disabled/missing saved ports retain dormant routes. VST3 keeps all declared buffer slots even for inactive buses; AU output pulls share timestamps.

Device output remains stereo: hardware output pairs are pending. VST2, Windows DLLs and Windows plugin-state migration are not implemented. Plugin binaries must support the application’s architecture. Discovery and validation run in separate processes with time/output bounds; runtime processing remains in the app process, so a faulty third-party plugin can crash it. Absolute and pattern-relative parameter automation are implemented, including a native graphical pattern-envelope editor. Arbitrary MIDI/SysEx output routing and controller-specific preset browsers remain pending.

Additional local qualification:

- A separately built VST3 fixture verifies effects/instruments, state recall, exact automation across 128/512-frame blocks at 44.1/48/96 kHz, tracker note-on/note-off, keyboard release, initial-state preservation, mixed sample/instrument latency alignment, and WAV parity. The measured fixture/host callbacks allocate, free and lock zero times.
- Native AU/VST3 custom windows pass attachment and close/reopen tests. VST3 custom-control edits reach the processor, record into the project timeline during actual virtual-device playback, and survive saving/reopening. Plugin windows reopen across playback restart.
- Apple DLSMusicDevice passes audible instrument rendering, note release and state recall. Real virtual-device PCM matches offline reference exactly for AU instrument, VST3 instrument with automation, VST3 effect with automation, AULowpass and dry playback: 96,000 stereo frames per case at 48 kHz / 512 frames, no timestamp gaps or callback overruns in the measured run.
- Installed Native Instruments Bite (13 parameters, reported latency 20 samples at 48 kHz) and FM8 (1,103 parameters, zero reported latency) pass isolated creation, rendering, parameter enumeration and state recall. These probes do not qualify every preset or vendor feature.

Cached discovery and Battery 4 fixes (2026-09-19):

- Plugin inventory is cached in memory and in the user's Caches directory, partitioned by architecture and schema version. The picker has an explicit **Rescan** button. Invalid caches are rebuilt; a failed full scan preserves the previous cache. Plugin validation still happens in an isolated process on add. Scanner diagnostics cannot contaminate JSON results.
- The supplied Battery 4 AU crash report identifies an off-main-thread HIToolbox assertion during `AudioComponentInstanceNew`. AU lifecycle and property/state calls now marshal to the main thread, while rendering and audio parameter delivery remain on the render path. A process-local test AU enforces that distinction and checks cleanup after failed initialization.
- Battery 4 VST3 was rejected by the old 16-bus cap. The host now provides the full bus arrays required by the VST3 contract, with inactive auxiliaries and the active stereo main output. A 32-output instrument fixture checks mono/stereo auxiliary layouts, activation and render buffer shape.
- Installed Battery 4 **4.3.0**, both AU (128 parameters) and VST3 (2,224 parameters), passes isolated MIDI/render/state probes and hidden actual-app load, state restore and removal. The 75-entry inventory took 30.507 seconds to rescan, 0.001536 seconds from memory and 0.285249 seconds on the first cached request after restarting the hidden app. These are inventory request times, not measured picker animation times.
- Probes use default plugin state, no custom editor and no hardware audio output. They do not qualify loaded kits, every preset, arbitrary output routing, or sustained playback performance. See [test evidence](../doc/mac-native-qualification/2026-09-19-battery/README.md).

## Measured audio envelope

The five-minute hardware stress and earlier visible UI measurements below predate the VST3/instrument expansion. They remain useful historical evidence, but do not qualify the expanded graph for sustained performance. The current plugin build has the shorter five-path loopback and correctness checks described above.

- 30 sample-for-sample comparisons against a separate stock libopenmpt process: seven fixtures at 44.1/48/96 kHz, plus later-order and two-sequence comparisons at each rate. Maximum observed sample difference **zero**, with matching frame counts. Comparisons render at most 30 seconds per fixture.
- Core render instrumentation: zero intercepted allocation/release/pthread lock calls, including first-use rendering. The test proves its interposer detects an allocation, release and lock before trusting the counters.
- Dense 60-second offline workload: 127 channels, 1,024 rows, concurrent edits/audition/panic, 250 peak voices. Recorded runs reached 248–250 voices with zero intercepted allocation/release/lock calls. Accelerated offline wall-clock maxima varied from 158.25 µs to 6,892.71 µs with host scheduling; these are resource-safety tests, not device deadline qualification.
- Real-device five-minute workload: 127 channels, live edits/audition, AULowpass; 112,504 callbacks, maximum 1,751.54 µs, p99.9 ≤150 µs, **zero measured deadline overruns**. The 128-frame period at 48 kHz is approximately 2,667 µs.
- Three separate start/stop runs and a live AU run also pass. Callback duration is not a hardware loopback measurement or a complete device xrun counter.
- Virtual output/capture loopback through the installed BlackHole 2ch device: dry and AULowpass each matched 96,000 stereo frames exactly at 48 kHz / 512 frames. No capture timestamp gaps or callback overruns. System default routing and the virtual device’s existing configuration were preserved; this is not physical hardware loopback.
- Float32 stereo WAV export at 48 kHz: exact dry-core comparison, independent AU output comparison, frame-count/latency/tail checks, atomic replacement and failed-export preservation. The one-hour limit fails explicitly.

These are measured workloads on one machine, not guarantees for arbitrary songs, plugins or hardware. Live playback uses bounded loop-state storage and reports exhaustion rather than allocating on the audio thread.

## UI qualification

The app uses AppKit controls and a virtualized Metal pattern view paced at 60 fps. Actual UI inspection covered pattern/sample/instrument/effect views, compact sample layout, instrument creation and ADSR application, native project saving/reopening, retained AULowpass parameters, Space transport, numeric envelope-node edits/deletion, effect removal/undo with parameter restoration, and order insertion/move/removal/undo. Sequence switching and native file opening were subsequently verified. Auxiliary windows restore main-window focus. Intermittent inspection timeouts after closing an auxiliary window did not show an application hang: its main event loop remained responsive and Command-O opened the file dialog. Interface tests also check long-name compact layouts, keyboard transport/remapping and note release, envelope-node editing/deletion, and access to 5,000 orders.

A **60-second visible combined smoke workload passed its then-current checks**: 127 channels, live scrolling/editing, AULowpass, 300 edits, 15 undo/redo cycles and 3 saves. It measured 59.948 mean presented fps; p99 presentation interval 16.667 ms, CPU 0.651 ms and GPU 0.237 ms; 3 missed presentations among 3,449 measured intervals; zero audio overruns. Its CPU metric included drawable acquisition.

The **600-second attempt failed**, and its raw report is retained. The Mac locked during measurement: visibility/presentation checks failed, main-thread drawable acquisition stalled, and one audio callback reached 2,910.541 µs, exceeding the 2,667 µs deadline. The audio overrun is not waived. This result does not pass the sustained UI or audio release gate.

A corrected-metric attempt ended after 46.6 seconds when the window became hidden: audio had zero overruns, but visibility and presentation checks failed. Two subsequent attempts could not establish stable visibility. The current runner waits for stable visibility, temporarily keeps its test window above ordinary windows and prevents idle display sleep, aborts on occlusion, ignores invalid presentation timestamps and reports CPU preparation, drawable wait and total main-thread drawing separately. Reports identify their exact source build and whether measurement started. Progress writes stay off the main thread. The visible rerun is **blocked by an unavailable desktop/capture surface**. Native sequence/file-picker workflows are verified, but the main view currently reports 0 presented fps and coordinate/scroll actions encounter unavailable-window errors even after raising it. Accessibility actions and audio playback remain responsive. No final ten-minute 60 fps or 30-minute combined audio qualification is claimed.

The plugin expansion was inspected in the running application: the rack showed the restored tracker-instrument assignment and opened the VST3 plugin's custom window. Automated AppKit tests additionally verify control-to-audio changes, automation recording during virtual-device playback, and AU/VST3 window close/reopen. The subsequent VST3 60-second visible workload never began measurement: the window was occluded and the application inactive. The UI tool then explicitly reported that the Mac was locked. This remains an unverified performance gate, not evidence of 60 fps or audio deadlines. See [plugin qualification evidence](../doc/mac-native-qualification/2026-09-19-plugins/README.md).

## Reproduce

Run `bash mac/test.sh`; use `--device` for a brief device test, or `--soak 300` for the five-minute audio-only workload. `bash mac/sanitize.sh` runs memory/undefined-behavior checks separately from timing. Fidelity results are in `bin/mac-native/audio-test-results.json`; stock tests are in `bin/mac-native/stock-test-results.log`.

With the display unlocked, run `bash mac/ui-test.sh 600`, then `bash mac/ui-test.sh 1800 --no-build` for the longer combined gate. Reports are saved under `bin/mac-native/qualification/`. Build the ZIP with `bash mac/package.sh`. Hardware loopback, additional devices/displays/OS versions and a broader real-song/plugin corpus remain unqualified.
