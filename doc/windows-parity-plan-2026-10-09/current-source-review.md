## Refinements governing implementation

**P0b admission must be atomic across native owners and the worker.** Current `installCandidate` stages fallible view/operation objects before calling `beforeCommit`, then calls `onMain(stop_)` before swapping ownership. Merely adding an early `protectUnsaved()` call does not cover messages pumped during loading or that later main-thread callback. Add a document-replacement admission port distinct from audio/device hooks. Capture a value-only departure token on the UI owner; stage the replacement on the worker; revalidate token and take state in the final UI admission callback. Hold a short native departure lease until adoption or rollback so another raw edit cannot slip between validation and replacement. Specify cancellation and refusal of document-scoped writes during that lease; never block the UI waiting for a worker that is itself waiting for UI service. Constructor/initial-load paths with no previous document must remain valid. Recovery's existing fingerprint check is additional protection, not a replacement for owner generations.

The [handoff owner table](handoff-details.md#p0b-native-draft-protection) includes inline FX/nudge, precise notes, instruments, all automation curves, formula/bank children, sample/scratch drafts, Mixer/plugin/graph fields, routing/trims/forms, arrangement/timing/activity, import/render jobs and recording. Add plugin-path repair drafts to that audit (`PluginPathWindow.hpp` and graph recipe path workflows): they are document/plugin-targeted, while library filter/search or global device preferences alone are not song drafts. Raw invalid text counts even when it has not produced a model candidate. Read-only telemetry and selection do not count. Pending or uncertain writes require reconciliation; a cancelled chooser or failed open retains all drafts. A successful replacement retires only the consented old-document generations.

**Shared logic is extracted by behavior, not by directory.** Reuse portable Windows validators/operations/codec implementations after conformance establishes the intended contract. Start with Mixer control candidates and track operations. Keep worker queues, HWND/AppKit ownership, native serializers' boundary conversions, device notifications and plugin embedding native. A mechanical CMake/TU move is separate from a semantic refactor. Both adapters change in the same merge or behind a compile-compatible shim; temporary branches converge on main.

**Do not replicate the peer's unsupported prescriptions.** Compatible opaque effect replacement and live recorded-point editing already exist. Do not add duplicate paths or turn live point edits into stopped-only behavior. Do not automatically rebase stale writes from one unchanged field, infer complete inaccessibility from absent custom UIA code, permit arbitrary allocator growth on no-edit saves, quarantine required tests to get green status, impose 30-day recovery deletion, or require pixel-identical Mac controls. Keep all B01–B14 at the final gate, including recording/recovery/plugins/audio.
