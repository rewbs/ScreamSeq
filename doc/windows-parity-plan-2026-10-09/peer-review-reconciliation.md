## Architecture and workflow proposals adopted with boundaries

1. **Typed goldens and API conformance before migration.** The supplied fixture comparator's ordinary Python equality can conflate bool/int/real. Add typed tree comparison, exact binary preservation and source-protection checks. Keep exact known discrepancies as a temporary ratchet, never as permanent waivers. Add a documented method/parameter exception table and execute the same cases through the real pipe/socket adapters.
2. **Reuse portable Windows code.** Its metadata/preservation implementation is a credible shared-code candidate and already has Mac compilation entry points. Extract into a portable semantic codec rather than introducing a third codec. Keep platform file/UUID/locking/publication services outside it. Compare Foundation value types carefully; move container writing last.
3. **Single build source lists and accurate ownership.** Consolidate common CMake definitions and relocate already-shared files in a mechanical batch. Preserve flags, target inventories, standalone tests and attribution. Forwarding headers may ease a temporary migration, but all production callers should converge on the new location.
4. **Shared validators, history policy and pure presentation.** Reuse code after defining invariants. Share integer/UTF-16/identity validation, lane/field/clipboard formats, multisample grouping and command IDs. Native view state and callback dispatch stay native. Do not equate different Undo retention budgets with different musical results.
5. **Gesture-end commits.** Adopt one Undo per completed direct gesture, with bounded preview where supported. Retain explicit Apply for compound forms/imports/transform previews. Stage editor-by-editor rather than replacing every retained draft at once. Only rebase when the entire operation dependency set remains valid.
6. **Native discoverability and accessibility.** Add generated Win32 menus and command availability, semantic theme tokens, system high contrast, measured typography/layout, tooltips, UIA peers and compact/mixed-DPI checks. UIA work accompanies each surface instead of being deferred to a final cosmetic phase.
7. **Graph reachability before canvas expansion.** Map forms, buttons and context menus before declaring actions absent. Expose selection/note/group/preset/port actions and source navigation through common commands. Then improve direct manipulation, breadcrumbs and projection fidelity in small slices.
8. **Build-cost reduction.** Consider Main.cpp TU splitting when stable owner boundaries are touched, impact-selected checks, toolchain-sensitive caching and automated reciprocal fixture artifact exchange. Maintain meaningful assertions and foreground/device gates.

## Sequence and decisions

**Adopted sequence change:** P0a green builds/take protection → P0b safety and P0c typed conformance/harness → P1 Mixer → P2 tracks → domain slices on shared main. UI foundations may move earlier when independent, but a universal theme/docking/SessionCore rewrite is not a prerequisite to every feature. Mac regression protection is included in each shared slice and the reciprocal final gate.

The peer supplied fourteen decision prompts. Most are routine implementation recommendations that do not require blocking user input: small generated fixture corpus, scoped existing JSON use, reviewing rather than blindly adopting the Mixer proposal, stable command IDs, typed numeric policy, supported compiler repair and one-main integration. The plan states recommended behavior and requires compatibility tests instead of asking the user to choose low-level implementation details.

No decision blocks the first batch. Required device/commercial-plugin support and any reduction of the currently assumed platform/architecture scope still genuinely require user input before qualification/release. Branch protection settings, paid/available runners or new automatic recovery-deletion policy may require owner authorization when proposed concretely; none is changed or needed to complete this plan. Mac defects that threaten shared correctness or the integration gate are in scope; discretionary Mac restyling is not.
