# Native editor action mapping

This extends the [419-command inventory](command-inventory.csv) and [core command map](handoff-details.md#core-command-mapping). Row numbers below are `reference_row`, not screenshot numbers. Source was read at main `ffe81aa4b` and candidate `d5b7a09eb`; relevant candidate differences are called out. **Existing** means a native handler is present, not that the Mac and Windows interactions or failure paths have passed runtime acceptance. **Partial** names the available workflow and remaining difference. **Question** deliberately avoids declaring a control missing from an untraced path.

Paths are relative to the repository. Source functions and enum identifiers are more stable entry points than line numbers after refactoring. Follow the named `action`, `execute` or command handler to the guarded Session method. Native controls still need registration in the shared semantic command catalogue, with context, disabled reason, local text-key precedence and a captured target. Do not route a contextual command by whichever bus/plugin happens to be selected later.

## Acceptance and implementation implications

Every row retains its A01–A18 and phase mapping in the CSV. For each new command binding, verify the correct native owner receives it with text/IME focus, live musical typing, canvas focus, dirty fields, hidden panels, pending worker calls and stale/deleted targets. Availability is checked at dispatch as well as when rendering the menu. Reopening an owner and selecting a new target are separate actions.

The evidence-backed corrections above should reduce duplicate work: preserve existing Activity zoom, local editor commands, numeric group/annotation/reroute workflows and song modulation controls. The remaining work is command discoverability, context, direct interaction and missing scope-specific paths. Runtime-only items stay questions until the future native acceptance passes; no new runtime pass is claimed by this audit.
