## Recommended first implementation batch

**P0b retained-work safety, remaining M–L effort, high risk.** This is the first implementation recommendation, not permission to execute it. It prevents loss or duplicate side effects before more gesture/editor paths are added. P0a is already on main. The later sequence remains P0c conformance → P1 Mixer → P2 tracks, with P3a/P3c able to start earlier at their documented dependencies, then P3–P7 domain batches and P8 final integration.

### P0b.1 Complete uncertain-operation contracts

Reuse `WriteOutcome`, `CompletedCall` and `NativeWriteCompletion`. Define a readback/recovery strategy per side-effect domain: document imports/renders, plugin state/path repair, capture take lifecycle, library/catalogue/cache and file writes. Preserve operation/target/document/submitted generation and original result identity. Prefer preparing result storage before irreversible commit, but do not infer that this eliminates every uncertain outcome. A missing receipt is not a rejection, and an unchanged song token is not proof that a take/cache/file was unchanged.

For plugin reconnect, finish the existing uncommitted candidate. It captures stable plugin or graph/node, selected path/module hash and raw generation; known-result Review does not probe or reconnect again. It updates the saved-path display only when current document/revision matches the receipt, preserving a later draft. Its `invokePath` preflight classification begins inside the method; controller revision checks and vendor-editor flushing occur earlier. Review those boundaries explicitly: a stale refusal or failed flush must not be confused with a successful reconnect, and a generic error without a receipt must not enable retry. A committed path result and machine-local scan/cache changes are separate outcomes. Preparing a JSON reply early reduces one failure window but does not make later receipt allocation, native refresh or process loss infallible.

For recorder Start/Stop/Discard, capture take identity and distinguish a missing original take from a newer take; readback must never stop/discard a replacement. Define recovery behavior when process loss makes certainty unavailable. Keep unresolved work retained with an actionable explanation; do not enable blind retry.

Acceptance: known success, proven precommit refusal, postcommit completion failure, generic unknown without receipt, foreign nested receipt, cache eviction, new document/revision/take and later typing. Every case preserves the right raw generation and produces at most one side effect/Undo. Cheapest checks are value-state and operation fault cases, followed by the relevant real-HWND owner and actual-pipe cases on one coherent Windows build. Shared outcome changes require both platform builds and affected adapter checks; no full unrelated DSP suite for UI-only completion work.

Concrete reconnect checkpoint: extend `DocumentControllerTests.cpp` publication cases for preflight outcome and original result identity; retain `Workspace/NativeWriteCompletionTests.inc::pluginPathCompletionReview`. Reuse the actual-pipe scenarios in `test_plugin_paths.py`: stale/deleted/unsupported targets, module-hash and vendor-state refusal, graph recipe identity/connections, and native reconnect draft/chooser behavior. Use the redistributable provider cache for deterministic coverage; installed commercial-plugin cases are a separate vendor gate. Build app, controller and affected workspace owners once after the candidate is coherent, then run those scenarios. Controller or common dispatch changes additionally require draft census, workspace restore and relevant API replay checks. Do not run a full DSP suite merely for native result labels; preparation/publication changes trigger the relevant provider/live-state tests. Preserve every saved recipe field except the deliberately changed path, one Undo, later raw text and failure retention through save/reopen.

### P0b.2 Final document admission and complete owner census

Use `editor/DocumentDeparture.hpp`, `DocumentDraftRegistry.hpp`, `DocumentDrafts.inc`, native owner summaries and `DocumentReplacementAdmission`. Capture immutable consent over document/revision, owner incarnation, target and raw generation. Review raises the same owner; Discard authorizes only that snapshot; Cancel revokes consent. Pending/uncertain work cannot be discarded by aggregate permission. Failed summary reads fail closed.

Add explicit native owner retirement after successful adoption; the current registry has no discard/retire callbacks. Connect Application to the optional observer for native/API Open and recovery, and apply the same policy to Close and bounded `WM_QUERYENDSESSION`. New/Demo in P3c reuse it. Preserve both take guards at final admission. Hold a short input/API lease through worker adoption, native refresh and old-owner retirement, while servicing callbacks needed to avoid deadlock. Gate native input before controls mutate, including synchronous messages; ignoring `EN_CHANGE` after mutation is insufficient. Failed chooser/parse/preparation/Stop preserves original song and drafts. Postcommit UI failure instead reconciles the committed state without resending the operation.

Acceptance: every owner family, hidden/floating/docked owner, nested formula/bank, Main FX/nudge/sample/mixer/plugin/graph/direct-render owner, raw invalid/stale text, newer work during consent, failed summary, canceled chooser and take creation during message pumping. Run pure consent/reentrancy cases first, then full real-owner census and actual Open/API/recovery/Close/session-end scenarios. Changes to common dispatch, native controls or lifetime management trigger workspace restore, shortcuts, typing and recovery coverage. Mac shared departure/header/session/shutdown checks are required when those contracts change; Windows native tests do not substitute for them.

Freeze a coherent candidate before the expensive app/workspace compilation. Reuse the matching direct-result cases above; add newly necessary unknown-result and departure scenarios. Include the branch's graph role/cable repairs and both recording-take guards in the regression set. Carry each retained state through native Open, API Open, recovery and Close. A registry-only test is insufficient.
