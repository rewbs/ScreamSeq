### Concrete first slice and outcome protocol

**Recommended first implementation slice: P0b.1, completion outcomes and reconciliation.** It is the dependency for honest pending/uncertain summaries and safe departure. Keep the three completed owners; do not start Mixer or general SessionCore migration in this slice.

Committed-HEAD paths that motivated the slice (the partial working-tree delta above supersedes only the specified API/controller observations):

- `windows/Api/SessionAdapter.hpp::ApiError` currently holds only a code and message. `dispatch` captures the pre-write revision; a host write followed by failed `snapshot()` reaches a generic catch and can return that old revision. Successful writes are cached, errors are not. Existing cache bounds and busy retry identity remain contracts.
- `windows/Session/DocumentController.cpp::publishCommitted` and `invoke` report committed failures through the same `-32003` used elsewhere before mutation. `DocumentControllerTests.cpp::publicationTests` presently checks for the word “committed”. Replace message interpretation with typed assertions.
- `windows/App/Main.cpp::documentOperation` can finish the worker write then fail in `refreshDocument` or post-save completion. Its catch calls `refreshDocument` again, which can mask the original exception. Owners such as Mixer currently label every catch as rejection; multisample, render and recording callbacks also run after the write and must preserve its actual outcome.

Proposed portable value contract: `CommitOutcome { NotCommitted, NoChange, Committed, Unknown }`, with optional committed document/revision, submission identity and a separate completion/publication diagnostic. Names may follow local conventions. `NotCommitted` is asserted only at a boundary that proves no effect; absence of a revision delta does not prove it for a clean-file save, catalogue operation, take or external plugin effect. Leave unknown outcomes unknown until reconciled. Preserve public error codes and ordinary error shapes; add structured outcome details for classified writes and document them in the API guide/schema. Never infer outcome from numeric code or message wording.

The worker supplies the outcome at the actual commit boundary. The native adapter preserves it through best-effort view repair. Each owner retains its submission token, raw generation and target until it can reconcile the result; newer raw fields survive. A committed result must not be retried as a new write. A successful host call followed by envelope/snapshot failure must not enable duplicate side effects under request replay: preserve a bounded outcome receipt or require explicit reconciliation, with deterministic behavior for same-ID/same-content and same-ID/different-content requests. Do not redesign all Mac/Windows cache policy here; P0c owns full protocol convergence.

### Admission and exit contract

1. Capture a read-only UI-thread summary of all owners, document/revision and take identities after ordinary saved-state protection. Never parse controls on the worker or run callbacks that pump messages during summary enumeration.
2. Present native **Review / Discard / Cancel**. Review raises the existing owner without Reload or Apply. Cancel preserves raw values, selection, caret, focus, playback and document. Discard authorizes only the captured owner incarnations/generations/targets; it does not erase work yet. Pending/uncertain operations cannot be discarded as if known uncommitted.
3. After file choice, candidate decoding/cache construction and recovery fingerprint checks, perform final admission. A changed document, new take, newer raw text, owner recreation, failed summary or stale token refuses without losing the current song. API replacement receives a structured refusal and never opens a modal prompt on behalf of a pipe client.
4. Supply `DocumentReplacementAdmission` from Application, with lifetime longer than the controller. During its short lease, block/defer document-scoped keyboard, mouse, clipboard, menu, child-control messages, queued commits and API writes **before native controls mutate**. Disabling buttons or ignoring EN_CHANGE after WM_SETTEXT is insufficient. Continue worker/main-thread service callbacks and harmless presentation so the lease cannot deadlock plugin/publication work.
5. Keep the lease through model adoption, visible state refresh and old-owner retirement. `finish(true)` must not release before the UI represents the new document; it is `noexcept`, so design refresh/retirement failure behavior explicitly. Candidate/Stop/admission failure releases the lease with all prior owners intact. Retire only the exact consented work after successful adoption.
6. Route native Open, API Open and recovery through that boundary. New/Open Demo later inherit it. Close and `WM_QUERYENDSESSION` need a bounded equivalent protocol, including recovery flush and both take rechecks; do not force an interactive indefinite worker wait during OS shutdown. Define and test refusal/deferred-close behavior. No blanket plugin teardown while UI-thread callbacks are still pending.
