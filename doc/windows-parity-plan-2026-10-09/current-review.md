Observed committed behavior:

- ApiError can carry NotCommitted, NoChange, Committed or Unknown. Known worker postcommit failures carry actual identity/revision. Main preserves the worker exception through best-effort refresh; a later callback failure is not allowed to impersonate the original operation's refusal.
- The adapter preflights strict response serialization and the 32 MiB wire limit before caching. A host return followed by snapshot/envelope failure becomes Unknown without a misleading pre-write revision.
- The existing 64-entry / 8 MiB FIFO can retain classified committed/unknown errors as well as successes. Its replay guarantee is bounded, best effort and non-durable. Same ID is not a universal exactly-once mechanism after eviction, nonretention or restart.
- API guide/schema are updated for this optional error detail. Native owners still need retained submission results and reconciliation actions; absence of outcome or an unchanged song revision proves no rejection of file, catalogue, device, take or plugin effects.

### Admission and exit contract

1. Capture a read-only UI-thread summary of all owners, document/revision and take identities after ordinary saved-state protection. Never parse controls on the worker or run callbacks that pump messages during summary enumeration.
2. Present native **Review / Discard / Cancel**. Review raises the existing owner without Reload or Apply. Cancel preserves raw values, selection, caret, focus, playback and document. Discard authorizes only the captured owner incarnations/generations/targets; it does not erase work yet. Pending/uncertain operations cannot be discarded as if known uncommitted.
3. After file choice, candidate decoding/cache construction and recovery fingerprint checks, perform final admission. A changed document, new take, newer raw text, owner recreation, failed summary or stale token refuses without losing the current song. API replacement receives a structured refusal and never opens a modal prompt on behalf of a pipe client.
4. Supply `DocumentReplacementAdmission` from Application, with lifetime longer than the controller. During its short lease, block/defer document-scoped keyboard, mouse, clipboard, menu, child-control messages, queued commits and API writes **before native controls mutate**. Disabling buttons or ignoring EN_CHANGE after WM_SETTEXT is insufficient. Continue worker/main-thread service callbacks and harmless presentation so the lease cannot deadlock plugin/publication work.
5. Keep the lease through model adoption, visible state refresh and old-owner retirement. `finish(true)` must not release before the UI represents the new document; it is `noexcept`, so design refresh/retirement failure behavior explicitly. Candidate/Stop/admission failure releases the lease with all prior owners intact. Retire only the exact consented work after successful adoption.
6. Route native Open, API Open and recovery through that boundary. New/Open Demo later inherit it. Close and `WM_QUERYENDSESSION` need a bounded equivalent protocol, including recovery flush and both take rechecks; do not force an interactive indefinite worker wait during OS shutdown. Define and test refusal/deferred-close behavior. No blanket plugin teardown while UI-thread callbacks are still pending.
