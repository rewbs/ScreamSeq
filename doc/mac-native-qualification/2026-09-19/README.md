# Local development qualification evidence

These results describe an Apple M2 Pro MacBook Pro (Mac14,9, 32 GB) running macOS 26.5.2, with the built-in speakers as the default output at 48 kHz / 128 frames. The upstream baseline is `f83cedb0cd5446e4dfaa83ac97e3087107e26767`. Source fingerprints and build/package hashes are recorded in `manifest.json`; this is a local development build, not a public release certificate.

- `audio-fidelity.json`: 30 exact, finite PCM comparisons against the separately compiled stock engine at 44.1/48/96 kHz, including later-order seeking and two song sequences. The render audit checks allocations, releases and pthread locks, including first use.
- `suite-summary.log`: final stock/editor/effect/session/recovery/interface/export/stress/MIDI/device run. Offline stress wall-clock timings are not real-time device deadline qualification.
- `sanitizer-summary.log`: AddressSanitizer/UndefinedBehaviorSanitizer correctness checks; exclude these timings from performance claims.
- `audio-300s-initial.log`: earlier five-minute actual Core Audio/AULowpass run, with 127 channels and live edits/audition. The final five-minute rerun is recorded in `suite-summary.log`.
- `audio-virtual-loopback.log`: actual Core Audio output captured through BlackHole 2ch. Dry and AULowpass each matched 96,000 stereo frames exactly at 48 kHz / 512 frames, with no timestamp gaps or callback overruns; this does not measure physical hardware latency.
- `ui-60s-initial.json`: passing one-minute visible smoke workload on an earlier build, with audio, edits, undo/redo and saves. It does not satisfy the ten-minute release gate.
- `ui-600s-initial.json`: **failed** ten-minute attempt. The display locked and presentation/CPU checks failed. One audio callback also exceeded its deadline; that failure is retained and not waived.

The initial UI reports predate source-fingerprint reporting and the corrected occlusion/drawable-wait measurements. They must not be represented as qualification of the latest binary. The later reports preserve additional failures: `ui-60s-occluded.json` ended after 46.6 seconds with zero audio overruns but failed visibility/presentation/main-thread limits; `ui-60s-hidden-start.json` became hidden immediately; `ui-60s-no-visible-window.json` could not establish stable visibility. The desktop/capture surface is currently unavailable. `ui-startup-blocked-current.json` explicitly records `measurementStarted: false` and zero measured duration. The updated harness distinguishes startup failure from measured work. Native sequence switching and module opening were verified afterward, but the main view still reported 0 presented fps and scrolling failed with unavailable-window errors. The root cause of this desktop state is not established. A separate launch through macOS Launch Services reproduced the blocker on the final packaged source build; `ui-launchservices-blocked.json` records an existing, non-minimized, non-hidden window that macOS considers fully occluded, with the app inactive and renderer paused. No measured workload started. The ten-minute presentation gate and 30-minute combined audio/UI gate remain open. Hardware listening/loopback and broader device, OS, display, real-song and plugin coverage are also outstanding.

With the display unlocked and the app visible, reproduce with `bash mac/ui-test.sh 600` and `bash mac/ui-test.sh 1800 --no-build`. Each current report includes its process identity and exact source fingerprint. See [the progress report](../../MAC_NATIVE_PROGRESS.md) and [compatibility matrix](../../../mac/COMPATIBILITY.md).
