- Built-in detector inputs and AU inputs that were fully allocated during preparation can receive their first live connection. The logical port can start inactive. A connected prepared input has current audio telemetry. - Fixed-topology recipe parameters, source settings, depths, curves and edge gains publish to all prepared ordinary/row/persistent/sample-instrument copies. A root song-source edit after engine construction no longer makes subsequent recipe controls appear structurally incompatible.
- Full opaque recipe state can replace one plugin node in every copy, retaining other vendor instances. The stable endpoint fades old/new states for 10 ms, fans out parameter events during the fade and keeps both owners off the callback. A second opaque replacement waits for the first fade. Descriptor, physical buses, latency and parameter identities/ranges must match. AU and VST fixtures change hidden audible state without changing exposed parameters, proving the full bytes are used.
- Linked bank changes affecting recipe/root controls and ordinary automation lanes share one adoption boundary. Native-only Undo/Redo stages all allocation and publication before no-throw history adoption. The actual-device fixture covers grouped rack and compound bank history.
- Rack parameter queries expose optional `manualValue` from the control-owned manual/preset catalogue. The existing `value` remains the effective vendor value. Queued manual edits update the editable base immediately; pattern/recorded scheduled baselines and modulation do not overwrite it. UI/API integration is tracked separately.
- Recipe modulation can explicitly target writable stepped parameters. All enabled cables into the same parameter agree on continuous/discrete mode. The host adds source contributions, clamps once, then quantizes by the actual plugin catalogue step. Mac VST3 now exposes normalized `1/stepCount`; AU indexed/boolean/MIDI-note and builtin choice/boolean controls expose unit increments.
- Bare songs and simple implicit racks retain stock integer summation for exact export. Actual native routing prepares an implicit mixer on a playback copy. Device playback explicitly prepares its graph for live editing.

## Discrete delivery bounds

Each prepared recipe processor has at most 64 modulated targets. Runtime source values use fixed 32-sample scratch arrays. VST3 receives at most 16 sample-offset values per parameter inside each processor call, preserving actual abrupt discrete values even when a vendor interpolates its parameter queues. It does not simulate every value change with a one-sample audio buffer. The actual VST fixture verifies zero one-sample process calls for aligned 512/4096-frame outer buffers, including a full opaque preset crossfade and the maximum 64 targets. Genuine caller/point/event boundaries may still naturally leave a one-frame remainder.

AU and builtins split at actual discrete value changes. Independent references apply the same values sample by sample, including builtin de-click smoothing. Shared tests compare partition sizes 1/7/17/128/512 across LFO, seeded random, Amount, MIDI, automation, follower and note-envelope sources, and verify summation before quantization. Continuous targets retain the previous curve/ramp path. New spans reject over-size and non-finite data before delivery.

Existing recipe mode changes can publish as fixed-topology controls when the catalogue supports that mode; disabling discrete mode on a stepped parameter rejects before publication. Adding/removing recipe nodes or cables remains subject to the topology limit below. Custom vendor editor changes remain an explicit template-publication step affecting all uses, as agreed for this pass.
